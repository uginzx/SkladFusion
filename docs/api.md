# API обмена с учётной системой

Сервер склада обменивается с учётной системой по HTTPS и JSON двумя запросами:

- **`GET /api/erp/inbox`** — всё, что пришло с телефонов и ждёт учёт (итоги сборки, фото, перестановки ячеек, вес и габариты, новые заказы, пересчёты). Длинный опрос: если ничего нет, сервер держит запрос, пока что-то не появится.
- **`POST /api/erp/push`** — подтверждения принятого и всё, что изменилось в учёте (товары, заказы к сборке, покупатели, виды цен).

Готовая реализация — [модули lsFusion](lsfusion.md). Другую учётную систему можно подключить по этому описанию.

## Общее

- Каждый запрос — с заголовком `X-Sync-Key: <sync_key из config.php>`. Неверный ключ — `401`.
- Тела запросов и ответов — JSON (`Content-Type: application/json`), UTF-8.
- Ошибка — HTTP 4xx/5xx и `{"error": "текст"}`. `409` — данные не приняты по смыслу (текст объясняет почему), `503` — сервер занят, повторите.
- Объекты идентифицируются GUID в нижнем регистре (`xxxxxxxx-xxxx-xxxx-xxxx-xxxxxxxxxxxx`). Если в учёте GUID нет, сделайте постоянный из внутреннего номера (например, `md5("item" + id)` в формате UUID) — модули lsFusion так и делают.
- **Всё повторяемо.** Повторная посылка ничего не дублирует, подтверждение можно прислать ещё раз. При любом сбое просто повторите проход.
- Даты — `YYYY-MM-DD HH:MM:SS` или ISO 8601, в часовом поясе сервера (`config.php` → `timezone`).
- Количества — с точностью до 0,001; вес — кг, габариты — см.

## Проход обмена

```
1. GET  /api/erp/inbox?wait=10      ← что пришло с телефонов
2. записать в учёт: новые заказы, итоги сборки, ячейки, вес и габариты, фото, пересчёты
3. POST /api/erp/push                → подтверждения шага 2 + изменения учёта с прошлой посылки
```

Проходы можно запускать один за другим без пауз: пока с телефонов ничего нет, `inbox` сам ждёт. Изменения учёта уходят не позже чем через `wait` секунд. Посылка не дошла — повторите её в следующем проходе (учёт помнит, что отправлено, только после успешного ответа). Раз в сутки присылайте полную сверку (`full: true`).

## `GET /api/erp/inbox?wait=N`

`N` — сколько секунд ждать, если ничего нет (0–25).

```json
{"results": […], "moved": […], "cells": […], "dims": […], "product_photos": […], "drafts": […],
 "inventories": […], "inv_active": false, "ver": 12345}
```

Пустые списки — ничего не ждёт. Каждый элемент отдаётся, пока учёт его не подтвердит в `push.ack`.

### `results` — итоги сборки

```json
{"guid": "<guid заказа>", "number": "ЗК-000123", "picker": "Иван", "finished_at": "2026-11-27 11:02:41",
 "complete": true,
 "lines": [{"n": 1, "guid": "<guid товара>", "char": "", "qty": 2, "picked": 2, "note": ""}],
 "photos": [15, 16]}
```

- Итог отдаётся не раньше чем через 2 минуты после «Завершить» (кладовщик успевает исправить).
- Фото коробки, снятые после передачи итога, приходят ещё раз тем же заказом — только новые. Файл: `GET /api/erp/photo/<id>` → JPEG.
- Подтверждение: `ack.results = {"guids": ["<guid заказа>"]}`.

### `moved` и `cells` — ячейки

`moved`: `{"guid", "was", "cell"}` — товары, у которых основное место в приложении разошлось с учётом. `was` — что было в учёте: если там тем временем поменяли руками, не перетирайте. `cells` — коды всех ячеек приложения (заведите недостающие).
Подтверждение: `ack.cells = {"items": [{"guid", "cell"}]}` — что теперь записано в учёте.

### `dims` — вес и габариты

`{"guid", "weight", "length", "width", "height", "ver", "was": {"weight", "length", "width", "height"} | null}`. Запишите, если в учёте всё ещё `was`.
Подтверждение: `ack.dims = {"items": [{"guid", "ver", "weight", "length", "width", "height"}]}` — что **теперь** в учёте у товара (даже если правку не приняли).

### `product_photos` — фото товаров с телефона

`{"id", "guid", "sku", "name"}`; файл — `GET /api/erp/product_photo/<id>` (JPEG до 2000 px).
Подтверждение: `ack.product_photos = {"ids": [1, 2]}`.

### `drafts` — новые заказы с телефона

```json
{"uuid": "…", "author": "Иван", "created_at": "2026-11-27 12:00:00",
 "customer": "<guid покупателя>", "customer_new": {"name": "Пётр", "phone": "+7…"},
 "price_type": "<guid вида цен>", "comment": "",
 "lines": [{"guid": "<guid товара>", "qty": 1, "price": 990}]}
```

- `customer_new` — `null` или новый покупатель: заведите его с GUID = `customer`.
- Сделайте GUID нового заказа равным `uuid` — тогда повтор после потерянного подтверждения найдёт уже созданный.
- Созданный заказ пришлите в `push.orders` — он встанет в сборку.

Подтверждение: `ack.drafts = {"items": [{"uuid", "number": "ЗК-000124"} | {"uuid", "error": "текст"}]}`.

### `inventories` и `inv_active` — пересчёты

```json
{"id": "<uuid пересчёта>", "maker": "Производитель", "user": "Иван", "finished_at": "2026-11-27T13:00:00+03:00",
 "lines": [{"guid", "sku", "book": 10, "picked": 2, "fact": 7, "delta": -1,
            "picked_orders": [{"order": "<guid заказа>", "qty": 2}]}]}
```

- `book` — остаток учёта в момент первого счёта, `picked` — сколько уже собрано в коробки активных заказов, `fact` — насчитано на полках, `delta = fact + picked − book` — разница, которую нужно провести.
- `picked_orders` — по каким заказам собран товар: если на списание не хватает свободного остатка, резерв лучше снимать сначала с заказов, где товар ещё не собран.
- `inv_active` — на сервере идёт пересчёт: присылайте остатки без задержки, чтобы они были свежими.

Подтверждение: `ack.inventories = {"items": [{"id", "ok": true, "docs": {"inv": "ИНВ-1", "in": "ОП-2", "out": null}, "unreserved": ["ЗК-000120"]} | {"id", "ok": false, "error": "текст"}]}`. Номера документов и заказы, с которых снят резерв, видны в приложении.

### `order_adds` — товары, добавленные в заказ (зарезервировано)

Появится, если сервер умеет добавлять товары в собранный заказ; в этой версии сервер его не отдаёт. Модули lsFusion уже умеют его принимать (`ack.order_adds`).

## `POST /api/erp/push`

Каждая часть необязательна:

```json
{
  "ack": {"results": {…}, "cells": {…}, "dims": {…}, "product_photos": {…}, "drafts": {…}, "inventories": {…}},
  "pricetypes": {"items": […]},
  "customers": {"items": […], "full": false},
  "orders": {"items": […], "full": false, "remove": ["<guid>"]},
  "products": {"items": […], "full": false, "cells": […]}
}
```

Порядок обработки: подтверждения → виды цен → покупатели → заказы → товары. Каждая часть в своей транзакции; ошибка части — HTTP-ошибка, сделанное до неё остаётся — повторите посылку целиком.

Ответ: `{"ack": {"results": {"acked": 1}, …}, "orders": {"received", "changed", "removed"}, "products": {…}, …}`.

### `products` — товары

```json
{
  "full": false,
  "items": [{
    "guid": "…", "code": "ТВ-00001805", "sku": "A-100", "name": "Насос ручной", "unit": "шт",
    "barcodes": [{"b": "4600000000001", "c": "", "u": "шт"}],
    "stock": 12, "ordered": 3, "price": 990.00,
    "prices": {"<guid вида цен>": 990.00},
    "maker": "Производитель",
    "weight": 0.35, "length": 30, "width": 8, "height": 5,
    "cell": "07-3",
    "deleted": false
  }],
  "cells": ["07-1", "07-2", "07-3"]
}
```

| Поле | Что |
|---|---|
| `barcodes` | `b` — штрихкод, `c` — GUID характеристики (или `""`), `u` — единица |
| `stock` | остаток на складе; `ordered` — сколько из него ждёт отгрузки по заказам |
| `price` | цена продажи для карточки товара; `prices` — по видам цен (для новых заказов с телефона) |
| `maker` | производитель: пересчёт делается по производителю |
| `weight`, `length`, `width`, `height` | необязательно. Применяются, только если изменились в учёте с прошлой посылки — правка с телефона не откатывается |
| `cell` | основная ячейка товара в учёте (необязательно). Тоже применяется только при изменении в учёте |
| `cells` | необязательно: коды всех ячеек склада в учёте — недостающие заводятся на сервере |
| `full` | `true` — полный список: товары, которых в нём нет, снимаются с телефонов |

Сервер сам находит изменения по отпечатку — на телефоны уходит только изменившееся. Предохранитель: полный список меньше 80% от прежнего (при > 100 товаров) отклоняется с `409`.

Код ячейки — буквы и цифры, `-` и `.`; штрихкод ячейки — `C` + код без знаков (кириллица как латиница). Код `07-3` (стеллаж-полка) даёт порядок обхода 703.

### `orders` — заказы к сборке

```json
{
  "items": [{
    "guid": "…", "number": "ЗК-000123", "date": "2026-11-27 10:15:00",
    "customer": "Иванов Иван", "comment": "Позвонить перед доставкой", "state": "Подтверждён", "urgent": false,
    "lines": [{"n": 1, "guid": "<guid товара>", "char": "", "char_name": "", "unit": "шт", "qty": 2}]
  }],
  "full": false,
  "remove": ["<guid заказа>"]
}
```

- По умолчанию (`full: false`) — только изменившиеся заказы, а снятые со сборки перечисляются в `remove`. `full: true` — полный список того, что нужно собирать: остальные заказы исчезают с телефонов.
- `qty` — сколько нужно собрать (например, ещё не отгруженное).
- Изменился состав уже собранного заказа — он возвращается в сборку, собранное сбрасывается. Изменение только шапки (комментарий) сборку не трогает.

### `customers` и `pricetypes` — для новых заказов с телефона

`customers`: `{"items": [{"guid", "name", "phone", "inn", "deleted"}], "full": false}`.
`pricetypes`: `{"items": [{"guid", "name"}]}` — полный список видов цен, доступных в новом заказе.

## Проверка руками

```bash
KEY=…; URL=https://sklad.example.com
curl -s -H "X-Sync-Key: $KEY" -H 'Content-Type: application/json' \
  -d '{"products":{"items":[{"guid":"11111111-1111-1111-1111-111111111111","code":"T-1","name":"Тест","unit":"шт","barcodes":[{"b":"2000000000015"}],"stock":5}]}}' \
  $URL/api/erp/push
curl -s -H "X-Sync-Key: $KEY" "$URL/api/erp/inbox?wait=0"
```

## API телефона и доски

Для интеграции с учётом не нужно, но описано в начале файлов: телефон — `server/src/api_app.php` (`/api/login`, `/api/sync`, `/api/events`…), печать — `server/src/api_print.php`, доска — `server/src/api_board.php`, обновление приложения — `server/src/api_update.php`, отгрузка — `server/src/api_ship.php`.
