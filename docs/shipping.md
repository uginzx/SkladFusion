# Отгрузка через внешнюю службу (необязательный модуль)

Если отправления создаёт ваш интернет-магазин или свой сервис доставки, склад может передать ему вес и габариты коробки прямо с телефона, получить трек и напечатать этикетку службы на принтер этикеток.

```
телефон → POST /api/orders/<guid>/ship → сервер склада (src/api_ship.php) → служба: POST <url>/ship
        ← трек                          ← GET <url>/label (PDF) → Ghostscript, 203 dpi → очередь печати → агент
```

Без настройки модуль выключен: экран «Отгрузка» пишет, что отправление создаётся вручную, а после сборки приложение возвращается к списку заказов. Когда модуль включён, после «Завершить» телефон сразу открывает «Отгрузку».

## Настройка

`config.php`:

```php
'shipping' => ['url' => 'https://shop.example.com/sklad-api', 'key' => '<общий секрет>'],
```

На сервере склада нужен `ghostscript` (`gs`). Размеры коробок — таблица `box_sizes`, заводятся с телефона; вес подсказывается как сумма весов товаров из учёта без коробки.

## Что должна уметь служба

Все запросы — с заголовком `Authorization: Bearer <key>`. Ответ — JSON с `"ok": true`; ошибка — `"ok": false, "message": "текст"` (текст увидит кладовщик; при HTTP 4xx — как отказ, при 5xx — как сбой). Ожидание ответа — до 90 секунд.

### `GET <url>/info?number=<номер>&guid=<guid>&date=<ISO 8601>`

Найти свой заказ по номеру и GUID заказа учётной системы. Не нашли — `{"ok": true, "order": null, "message": "почему"}`.

```json
{"ok": true, "order": {
  "id": 15,                       // целое число — id заказа в службе, дальше склад обращается по нему
  "created": "2026-11-27T10:15:00+03:00",  // необязательно: сильно расходится со временем заказа — «не тот заказ»
  "state_name": "Оплачен",
  "service": "Курьер",            // название службы доставки
  "shippable": true,              // служба создаёт отправления автоматически
  "address": "г. Москва, …", "customer": "Иван", "phone": "+7…",
  "tracking": "",                 // трек, если отправление уже создано (тогда склад его подхватит)
  "package": {"weight": 0, "length": 0, "width": 0, "height": 0}
}}
```

### `POST <url>/ship`

Тело — форма (`application/x-www-form-urlencoded`): `order` (id), `weight` (кг), `length`, `width`, `height` (см), `dry_run` (`1` — только проверить, ничего не создавать).

Ответ: `{"ok": true, "order": {"service": "Курьер", "tracking": "1234567890"}}`. Служба сама решает, что ещё сделать (сменить статус заказа, уведомить покупателя).

### `GET <url>/label?order=<id>`

Этикетка службы — `Content-Type: application/pdf`. Печатается первая страница в родном размере по центру выбранной этикетки; не влезает — уменьшается.

## Защита от двойных отправлений

Одно отправление на заказ: сервер держит блокировку на время создания, второе нажатие получает «Отправление уже создаётся». Если ответ службы потерялся, но отправление создано (у заказа есть `tracking`), следующий `info` его подхватит.
