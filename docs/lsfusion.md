# Подключение lsFusion

Модули в [`lsfusion/`](../lsfusion) — обмен с сервером склада для конфигурации на основе [MyCompany](https://github.com/lsfusion-solutions/mycompany) (lsFusion 7). Протокол — `/api/erp` ([описание](api.md)): длинный опрос `inbox` и `push` только изменений. Новое с телефона попадает в учёт за секунды, изменения учёта уходят на склад не позже чем через «Ожидание, с».

| Модуль | Что |
|---|---|
| `Sklad` | настройки, ключи объектов для сервера (GUID), вызовы сервера, журнал ошибок |
| `SkladBins` | ячейки — дочерние места склада (`Location`): штрихкод, порядок обхода, основная ячейка товара |
| `SkladItems` | товары, остатки, цены, покупатели → сервер; ячейки, вес и габариты, фото товаров ← сервер |
| `SkladOrders` | заказы к сборке → сервер; итоги сборки и фото коробок, новые заказы с телефона ← сервер |
| `SkladInventory` | пересчёты с телефона → документы корректировки (`Adjustment`) |
| `SkladSync` | проход обмена целиком, задание планировщика, форма «Обмен со складом» |
| `SkladTest` | верхний модуль для проверки: `MyCompanyRu` + обмен |

## Подключение

1. Положите модули рядом с модулями своей конфигурации и добавьте `SkladSync` в `REQUIRE` своего верхнего модуля (или запустите сервер с `-Dlogics.topModule=SkladTest` для пробы).
2. Если ячейки (бины) у вас уже есть в своём модуле, замените `SkladBins` своим с теми же свойствами (`barcode`, `walkOrder`, `binNote`, `in`, `mainBin`) или сделайте их на своих.
3. Если товары, контрагенты и заказы пришли из другой системы со своими GUID (например, при переходе с другой учётной системы), задайте их — тогда сервер склада узнает те же объекты:

   ```lsf
   skladExtId(Item i) += extGuid(i);
   skladExtId(Partner p) += extGuid(p);
   skladExtId(Sales.Order o) += extGuid(o);
   ```

   Без этого ключ объекта — GUID, выданный приложением склада (для созданного с телефона), иначе постоянный GUID из внутреннего номера объекта.
4. «Справочники → Обмен со складом»:
   - адрес сервера (`https://sklad.example.com`), ключ (`config.php` → `sync_key`), «Ожидание, с» (10–25);
   - склад (его дочерние места — ячейки), вид цен для приложения, тип заказа для новых заказов с телефона, «Подтверждать заказы из приложения (резерв)», «Заказы не старше, дней» (по умолчанию 60);
   - «Какие заказы собирать» — статусы заказов; «Виды цен в новом заказе»;
   - «Обменяться со складом сейчас» — один проход для проверки; «Включить обмен» — задание планировщика «Обмен со складом» (проходы один за другим).
5. Категории товаров, которые не нужны складу, — «Не выгружать в приложение склада».

## Как работает проход

1. `inbox`: сервер отдаёт всё, что пришло с телефонов (ждёт до «Ожидание, с», если ничего нет).
2. Шаги приёма, каждый в своей сессии (ошибка одного пишется в «Ошибки обмена» и не мешает остальным): новые заказы, итоги сборки (собрано по товарам, фото коробок, кто собрал), ячейки, вес и габариты, фото товаров (`SkladItemPhoto`; если у товара нет картинки — становится ею), пересчёты.
3. `push`: подтверждения принятого и всё, что изменилось в учёте с прошлой посылки (по отпечатку `skladHash`/`skladSentHash`); раз в сутки — полная сверка.

Посылка не дошла — отпечатки не запоминаются, в следующем проходе уйдёт заново; сервер принимает повторы.

## Проверка

[`lsfusion/tests/`](../lsfusion/tests): `phone_scenario.php` изображает телефон (собирает заказ с фото, переставляет ячейки, вводит вес, снимает товар, создаёт заказы, проводит пересчёт) на тестовом сервере склада, `check.py` после одного прохода сверяет lsFusion и базу сервера. Порядок — в [`tests/README.md`](../lsfusion/tests/README.md).

Локальный сервер склада для проверки — `php -S` с роутером, который задаёт свой конфиг:

```php
<?php // router.php
define('SKLAD_CONFIG', __DIR__ . '/config.test.php');
if (preg_match('~^/img/~', $_SERVER['REQUEST_URI'])) { return false; }
require __DIR__ . '/public/index.php';
```

```bash
cd server && php -S 127.0.0.1:8088 router.php
```
