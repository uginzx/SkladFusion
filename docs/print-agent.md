# Агент печати этикеток

Принтер этикеток (термо, 203 dpi, любой с драйвером Windows) стоит у компьютера, который и так включён. Телефон печатает через сервер:

```
телефон → POST /api/print → очередь print_jobs → агент на компьютере (GET /api/print/next раз в 3 с) → драйвер Windows → принтер
```

- **Этикетку рисует сервер** (`server/src/labels.php`): PNG 8 точек на мм, шрифт DejaVu, штрихкод Code 128. Команды принтера (TSPL/ZPL) не нужны, кириллица печатается картинкой.
- **Виды:** товар (из карточки товара), ячейка (из списка ячеек), коробка (из меню заказа и экрана проверки) и, если включена [отгрузка](shipping.md), этикетка службы доставки.
- **Размер** выбирают в окне печати на телефоне. Список общий (таблица `label_sizes`): 25×45, 20×45, 40×60, 70×120, 100×150; свой — «+ свой», убрать — долгое нажатие. Телефон запоминает последний размер отдельно для товаров, ячеек и коробок; агент ставит его странице в драйвере. `config.php` → `label` — запасной размер для заданий без размера.
- **Вёрстка под размер:** узкие этикетки (ширина < 35 мм) рисуются вдоль длинной стороны и поворачиваются на 90°; на мелких (короткая сторона < 26 мм) — только артикул и штрихкод.
- **Товар без штрихкода** при первой печати получает свой EAN-13 из внутреннего диапазона: `200` + цифры с конца кода товара + контрольная цифра (код без цифр — `201` + цифры из GUID). Он хранится на сервере (`extra_barcodes`) и приходит на телефоны вместе с товаром — наклеенную этикетку сразу можно сканировать. В учётную систему этот штрихкод не записывается.

## Установка

На компьютере с принтером, в PowerShell, без прав администратора:

```powershell
irm https://sklad.example.com/agent/install.ps1 | iex
```

Сервер подставляет в установщик свой адрес (`config.php` → `url`) и имя экземпляра. Установщик:

1. спросит имя и PIN сотрудника с ролью «владелец» и получит по ним ключ агента (`GET /api/print/key`, это `config.php` → `print_key`), затем выйдет из этого входа;
2. покажет список принтеров и спросит номер принтера этикеток;
3. скачает агент в `%LOCALAPPDATA%\SkladPrint` (у второго экземпляра — `SkladPrint-<instance>`) и запишет `config.json`;
4. заведёт задачу планировщика «Склад — печать этикеток» (запуск при входе в Windows, скрыто, перезапуск при сбое) и запустит её.

Журнал — `%LOCALAPPDATA%\SkladPrint\agent.log`. Проверка без принтера: в `config.json` добавьте `"file": "C:\\temp\\label.prn"` — драйвер напечатает в этот файл вместо принтера.

## Как работает

- Агент на связи, если обращался к серверу за последние 60 с — это видно в окне печати и в «Ещё» на телефоне.
- Задание, которое агент взял и не отчитался за 2 минуты, снова встаёт в очередь. Задание старше 15 минут не печатается: если принтер был выключен, старые этикетки не полезут разом.
- Агент повторяет отчёт о печати, пока сервер его не примет, — этикетка не выйдет дважды.
- Ключ агента меняется в `config.php` → `print_key`; после смены переустановите агент.

## API

Агент (заголовок `X-Print-Key`): `GET /api/print/next` → `{id, copies, w, h, png}` (PNG в base64) или `{}`; `POST /api/print/done {id, ok, error}`. Телефон: `POST /api/print {kind: cell|product|order, ref, copies, w, h}`, `GET /api/print/status`, `GET /api/print/preview`. Подробнее — в начале `server/src/api_print.php`.
