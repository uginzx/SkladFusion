# Безопасность

## Ключи и где они лежат

| Что | Где | Кто знает |
|---|---|---|
| `sync_key` — ключ обмена с учётной системой | `config.php`; в lsFusion — форма «Обмен со складом» | сервер и учёт |
| `print_key` — ключ агента печати | `config.php`; на компьютере с принтером — `%LOCALAPPDATA%\SkladPrint\config.json` | сервер и агент |
| `shipping.key` — секрет службы отгрузки | `config.php` и служба | сервер и служба |
| Пароль MariaDB | `config.php` | сервер |
| Ключ VAPID (Web Push) | `<storage>/push/vapid.pem`, создаётся сам | сервер |
| Ключ подписи Android | `android/keys/*.jks` + `android/keystore.properties` | тот, кто собирает приложение |

- Ключи генерируйте случайными: `openssl rand -hex 32`. Не используйте один ключ для разных целей и разных серверов.
- `config.php`, `keystore.properties`, `*.jks`, `local.properties` в git не кладутся (`.gitignore`). Права на `config.php` — `640`, владелец `root`, группа PHP-FPM.
- Сменить ключ: поменяйте в `config.php` и на другой стороне (учёт, агент печати — переустановить).
- Ключ подписи Android потерять нельзя (телефоны не примут обновление) — храните копию и пароли отдельно от сервера.

## HTTPS

- Сервер — только по HTTPS (в примере nginx `http://` перенаправляется). Приложение Android в релизе не ходит по `http://` (`usesCleartextTraffic=false`, адрес на экране входа принимается только `https://`).
- Сертификат — Let's Encrypt (`certbot`) или свой. lsFusion проверяет сертификат по хранилищу сертификатов Java.
- Ключи обмена и токены идут в заголовках (`X-Sync-Key`, `X-Print-Key`, `Authorization: Bearer`) — без HTTPS их можно перехватить.

## Вход сотрудников

- PIN — 6–8 цифр, на сервере хранится только хэш (`password_hash`). Пять неверных попыток по имени или двадцать с одного адреса за 15 минут — отказ `429` (таблица `login_fails`). Адрес клиента берётся из `X-Real-IP`, поэтому nginx должен подставлять настоящий (`fastcgi_param HTTP_X_REAL_IP $remote_addr`, см. пример конфигурации) — иначе ограничение по адресу можно обойти.
- Токен входа хранится на сервере хэшем, живёт 60 дней без активности. «Выйти» в приложении отзывает его. Потерянный телефон — «выйти на всех устройствах» у сотрудника на доске заданий, новый PIN отзывает все входы.
- Список имён сотрудников (`GET /api/users`) открыт без входа — это экран выбора «Кто работает?». Если это неприемлемо, закройте сервер от интернета (VPN, белый список адресов в nginx).

## Что доступно без входа

- `/img/<guid>.webp` — миниатюры товаров (их видит любой, кто знает GUID товара).
- `/p/<token>` — страница «Клиенту»: фото собранного заказа и его состав, `noindex`. Токен случайный, заводится при первом фото заказа; кому отправили ссылку — тот и видит.
- `/api/app/version`, `/api/app/apk` — приложение (чтобы телефон мог обновиться и с истёкшим входом).
- `/agent/install.ps1`, `/agent/sklad-print.ps1` — агент печати (ключ в нём не содержится, установщик получает его по входу владельца).
- `/board/` — оболочка доски заданий (данные — только после входа).

## Резервные копии

Копируйте регулярно:

- базу: `mysqldump --single-transaction sklad | gzip > sklad-$(date +%F).sql.gz` (пользователем из `config.php`);
- каталог данных `storage` (фото коробок и товаров, файлы доски, ключ VAPID, APK);
- `config.php` и ключ подписи Android — отдельно и зашифрованно.

Учётная система — главная по товарам и заказам, но всё, что сделано на складе и ещё не забрано учётом (итоги сборки, фото, пересчёты, ячейки), есть только на сервере.

## Обновления

Держите PHP, MariaDB, nginx и ОС обновлёнными. Перед обновлением сервера склада — копия базы и `storage`, после — `bin/migrate.php`.
